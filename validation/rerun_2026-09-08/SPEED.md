# 速度検証記録（0.3.0）

主指標は **callgrind の命令数（Ir）** です。この機械は他プロセスの負荷を受けるため壁時計時間は比較に使えません。
命令数は負荷に依存せず決定的で、同じ入力に対して再現します。再実行は次のとおりです。

```sh
pixi run -e cpp bench-ir                                   # 既定のスイープ
python tools/benchmark_speed.py --ir --stages estep --sizes 100,200,500,1000 --dims 2,3
python tools/benchmark_speed.py --ir --compare <別ビルドのacpd_bench>   # 版間のA/B
```

`cpp/bench/bench.cpp`（`-DACPD_BUILD_BENCH=ON`）が計測対象で、JSON 1行を出力します。
`--stage estep|rigid|analytic|nonrigid`、`--backend`、`--analytic-backend`、`--fgt-*` で条件を切り替えます。

## 1. 実装レベルの最適化（近似なし・数値は不変）

いずれも原コード比較84条件の値を変えていません。

| 変更 | 対象 | 命令数の改善 |
|---|---|---|
| 格子キーをインライン固定長化、スクラッチ再利用、行優先蓄積 | permutohedral E-step | blur **1.98倍**、no-blur **1.75倍**（n=400, d=3） |
| M-step を JacobiSVD → BDCSVD | 解析段全体 | n=100 **2.24倍**、n=300 **2.74倍**、n=1000 **1.56倍**（d=3, 30反復） |
| M-step を BDCSVD → 完全直交分解（COD） | M-step単体 | 次数6 **4.62倍**、次数8 **5.47倍**、次数10 **9.32倍**（n=500, d=3） |
| E-step の二乗ノルム巻き上げ・行優先化・逆数乗算 | 直接法 E-step | 下表の解析段合計に含む |

COD と BDCSVD は、階数不足時にどちらも**最小ノルム最小二乗解**を返し、同じ相対しきい値で階数を報告します。
実測では階数は全条件で一致し、当てはめ値の差は最大 4.6×10⁻¹² でした。
監査データの M-step 851回のうち階数不足は **0回**で、実運用では両者は同値です。
原コード比較の M-step 一致度は **5.9952×10⁻¹⁵ → 3.9968×10⁻¹⁵ と改善**しました。

### 解析段の合計（0.2.1 の同一ベンチとの A/B、25反復）

| n | d=2 | d=3 |
|---:|---:|---:|
| 200 | 1.58倍 | **3.20倍** |
| 500 | 1.33倍 | 2.23倍 |
| 1000 | 1.26倍 | 1.74倍 |

3次元で効果が大きいのは基底数 K=C(次数+d, d) が大きく M-step が支配的なためです。
n が増えるほど O(n²) の E-step が相対的に重くなり、M-step 改善の寄与は薄まります。

## 3. IFGT（`fgt`）の評価 — 本ライブラリの想定規模では採用しません

ユーザー要求により、CPD側を含めて選択可能なモードとして実装し、実測しました。**結論は「勝てない」です。**

### 精度は設計どおり制御できます

d=3、n=400/350、既定 order=5・cluster_radius=0.25 で、厳密和に対する最大相対誤差:

| σ² | 0.5 | 0.05 | 0.005 | 0.0005 |
|---|---|---|---|---|
| 最大相対誤差 | 1.4×10⁻⁶ | 3.9×10⁻⁶ | 5.6×10⁻⁶ | 4.9×10⁻⁶ |

被覆半径を h=√(2σ²) に比例させる格子クラスタリング（O(n) 構築）により、σ が小さくなっても誤差が破綻しません。
`cluster_radius` を 1.0→0.25 と縮めると誤差が単調に減ることを試験で固定しています。

### しかし速度で負けます

**FilterReg方向**（上表）: 全条件で direct より 2.5〜4.3倍遅く、格子より 6〜93倍遅い。

**ACPD方向**（`--stage analytic`, d=3, 20反復。格子が使えない唯一の場所）:

| n | direct (Ir) | fgt (Ir) | 倍率 | 既知対応RMS direct | fgt |
|---:|---:|---:|---:|---:|---:|
| 200 | 325,217,947 | 3,482,162,314 | **0.09** | 0.569 | 0.569 |
| 500 | 1,601,132,325 | 19,919,166,946 | **0.08** | 0.6669 | 0.6669 |
| 1000 | 3,737,667,675 | 65,473,006,312 | **0.06** | 0.6459 | 0.6611 |

n が増えるほど悪化します。

### 理由（実装の欠陥ではなく手法の性質）

IFGT の1ペアあたりコストは 項数×値列数 です。d=3・order=5 では項数 C(8,3)=56、値列 d+2=5 で **280 flops**。
direct は1ペア d+2=5 の距離と積和で **約8 flops** です。つまり IFGT はペア数を **35分の1未満**に減らして初めて勝てます。

ペア数を減らすには打切り半径内のクラスタだけを見る必要がありますが、
- 精度には小さい被覆半径 r_x/h が要る（測定では order=5 で r_x/h≤0.25 が 10⁻⁶ 級に必要）
- 速度には大きいセル/h が要る（1問い合わせあたりのセル数は (2⌈cutoff/cell⌉+1)^d）

の二つが正面から対立します。既定値ではセル=0.289h、cutoff=4h なので方向あたり14セル、3次元で 29³≈24,000 セル。
グリッド索引を入れても1問い合わせ24,000回のハッシュ参照が要り、direct の n 回のペア評価に対する損益分岐は
**n ≈ 7×10⁴ 点**と見積もられます。本ライブラリの想定規模（100〜1000点）から2桁離れています。

ACPD の σ² は焼き鈍しで小さくなるため、クラスタ数が n に近づき問い合わせ側の線形走査が O(n²) に戻ります。
permutohedral 格子が強いのは、単体分解のコストが d に依存し **h に依存しない**からで、この点が IFGT との本質的な差です。

**結論**: `fgt` は明示選択のモードとして残し、既定では使いません。ACPD段のE-stepは厳密な `direct` が既定です。
「格子が使えないから近似すべき」ではなく、「この規模では厳密計算が最速」というのが測定結果です。

## 4. 低ランクM-stepを採用しなかった理由

参考論文（arXiv 2006.06281）の低ランク近似は、古典CPDの M×M ガウス**運動核** Γ の固有値が急減衰することに依拠します。
本実装の M-step にその核はなく、対応するのは重み付き Taylor 設計行列（n×K）です。実測した特異値スペクトル:

| d | 次数 | K | 数値ランク(1e-12) | 条件数 |
|---|---:|---:|---:|---:|
| 2 | 10 | 66 | **66** | 4.0×10⁹ |
| 3 | 8 | 165 | **165** | 1.4×10⁸ |
| 3 | 10 | 286 | **286** | 8.2×10⁹ |

**数値ランクは常に K と一致し、低ランクではありません。** 切り捨てれば実際に使われている方向を捨てることになり、
無条件の高速化ではなく精度との交換になります。代わりに、同じ最小ノルム解を保ったまま分解を替える COD を採用しました
（4.6〜9.3倍、精度劣化なし）。この判断根拠は再実行できます:

```sh
python /path/to/spectrum.py     # 設計行列の特異値スペクトル
```
